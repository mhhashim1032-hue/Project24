Website migration checklist: before, during and after launch

A practical pre-launch and post-launch checklist covering URL inventory, redirects, metadata, crawlability, analytics and monitoring.

Before the migration

  1. Crawl the existing site. Export indexable URLs, status codes, titles, descriptions, canonicals, headings and internal links.
  2. Identify valuable URLs. Review organic landing pages, conversions, backlinks and pages with meaningful referral traffic.
  3. Prepare a URL map. Match each retired URL to the closest relevant destination. Record pages that should return 404 or 410.
  4. Preserve content and metadata. Keep important copy, titles, descriptions, headings, structured data and internal links unless there is a reason to improve them.
  5. Test the staging environment. Check navigation, forms, mobile layout, canonical tags, robots directives and XML sitemaps.

At launch

  1. Deploy permanent redirects and test representative old URLs.
  2. Remove staging noindex tags and broad robots.txt blocks.
  3. Confirm canonical tags point to the preferred production URLs.
  4. Publish the production sitemap and update internal links.
  5. Verify analytics and conversion tracking before traffic moves.

After launch

  1. Monitor 404s, 5xx errors, redirect chains and server latency.
  2. Compare old and new URL inventories and investigate important missing pages.
  3. Review Search Console indexing, sitemap processing and page experience reports.
  4. Track organic landing pages, conversions and branded versus non-branded traffic.
  5. Keep a migration log with dates, deployments and fixes.

Do not use a single traffic fluctuation as proof of success or failure. Compare equivalent periods, account for seasonality and inspect technical evidence.
